1.1 下载并安装 Audiokinetic Launcher

安装 Wwise 的第一步：获取官方启动器

什么是 Audiokinetic Launcher

Audiokinetic Launcher 是 Wwise 官方的客户端程序，集成了 软件安装、版本管理、示例项目下载、 账号管理 四大核心功能。所有 Wwise 相关组件都通过它来获取和管理。

操作步骤

  1. 打开浏览器，访问官方下载页面：
    https://www.audiokinetic.com/downloads 也可以直接搜索 "Audiokinetic Launcher download"
  2. 选择对应操作系统的版本进行下载：
    • Windows — 下载 .exe 安装程序
    • macOS — 下载 .dmg 安装程序
  3. 运行安装程序，按照安装向导的提示完成安装。 安装路径建议使用默认路径，避免后续环境配置问题。
  4. 打开 Launcher，首次启动会提示登录或创建 Audiokinetic 账号：
    点击 Log In 使用已有账号登录，或点击 Create an account 免费注册。 账号是免费的，注册仅需邮箱。认证考试也需要此账号。
🖥️ 截图参考：Audiokinetic Launcher 登录界面 [ 官方页面：Launcher 首次打开后显示 Log In / Create an account ]
💡 提示 登录后 Launcher 会自动识别你的账号权限和已安装的 Wwise 版本。所有下载和安装操作都会记录在你的账号下。

1.2 安装 Wwise 2021.1.x

选择正确的版本并在 Launcher 中完成安装

⚠️ 版本重要提示 Wwise-101 认证课程是基于 Wwise 2021.1.x 版本制作的。
请勿使用 2022.1 或更新版本——界面布局和功能已有变化，课程操作步骤将无法完全匹配。
建议安装最新的 2021.1.x 小版本（如 2021.1.14）。

操作步骤

  1. 在 Launcher 中切换到 WWISE 标签页。 该页面显示所有已安装的 Wwise 版本以及可安装的版本列表。
  2. 在页面中找到 Install New Version 区域，依次选择：
    • 第一级下拉 → All
    • 第二级下拉 → 2021.1
    • 第三级下拉 → 选择最新的小版本号（如 2021.1.14.8108）
    选版本号最高的那个即可，小版本更新通常是 bug 修复。
  3. 点击右侧的 Install 按钮。
  4. 在安装选项对话框中：
    • SDK 组件 — 建议全部选中（C++、.NET、Unity、Unreal 集成等）
    • 部署平台 — 至少勾选 Windows 和 Mac
  5. 点击 Confirm 开始安装。安装过程可能需要 15-30 分钟，耐心等待。
  6. 安装完成后，在 WWISE 标签页中该版本旁边会出现 Launch Wwise (64-bit) 按钮。
📦 截图参考：Wwise Launcher → WWISE 标签页 → Install New Version [ 官方截图：选择 All → 2021.1 → 最新小版本 → Install ]
📌 补充说明 如果在安装过程中遇到防火墙或杀毒软件拦截，请选择"允许"。Wwise 的某些组件需要网络通信权限（用于 Profiler 远程连接等功能）。

1.3 安装 Cube 演示游戏与课程素材

Cube 是 Wwise-101 课程专用的演示游戏，用于实时测试音频效果

什么是 Cube

Cube 是 Audiokinetic 官方提供的一个小型演示游戏。 你控制一个叫 Wwizard 的角色在一个小场景中移动、投掷冰宝石、 接触各种地面材质。它已经集成了 Wwise，你可以把在 Wwise 中制作的声音实时在 Cube 中听到效果。

  1. 在 Launcher 中切换到 Samples 标签页。
  2. 在列表中找到 Cube（或直接搜索）。
  3. 确保版本匹配：选择与 Wwise 相同的 2021.1 版本。
  4. 点击 Install，等待下载和安装完成。
🎮 截图参考：Launcher → Samples → Cube → Install [ 官方截图：Samples 标签页中的 Cube 项目，版本选择 2021.1 ]

1.4 启动 Wwise 并创建新项目

掌握正确的项目创建流程，为后续学习打好基础

操作步骤

  1. 启动 Wwise：在 Launcher → WWISE 标签页中， 找到已安装的 2021.1.x 版本，点击 Launch Wwise (64-bit)。 请选择 64-bit 版本。32-bit 版本功能受限。
  2. Wwise Project Launcher 弹窗：列出最近打开的项目（首次使用为空）。
  3. 点击左下方的 New… 按钮。
  4. 在 New Project 对话框中填写信息：
    字段填写内容说明
    Name Wwise Project Module 1 项目名称，可自定义
    Location 点击 … 浏览到 Module 1 文件夹 即课程素材中的 Module 1 文件夹
    Mac 用户可能会看到路径前缀 Y:\，因为 Wwise 通过模拟层运行，属于正常现象。
  5. 添加平台：在 Platforms 区域点击 Add… → 选择 Mac → OK（默认已有 Windows）。
  6. 导入出厂资源：在 Import factory assets to project 区域点击 Select None（保持项目干净）。
  7. 点击 OK 完成创建。
  8. License Manager 弹窗：提示当前使用免费试用模式（所有 SoundBank 合计限 200 个媒体资源）。 点击 Close——课程完全够用。

  • 标题栏显示 Wwise Project Module 1 - Wwise

两大核心层级结构

Audio 标签页
├── Actor-Mixer Hierarchy ← 声音设计的主要工作区
│ 组织所有声音对象、容器、Actor-Mixer（在这里"创造"声音）
├── Master-Mixer Hierarchy ← 混音总线层级
│ 定义总线路由、效果器、Ducking（在这里"混合"声音）
├── Interactive Music Hierarchy ← 交互式音乐专用
└── Audio Devices ← 音频输出设备
📌 核心认知 没有混音发生在 Actor-Mixer Hierarchy 中。所有音频的实际混合处理都在 Master-Mixer Hierarchy 的总线上完成。Actor-Mixer Hierarchy 只负责组织和触发声音。

2.2 导入音频文件

使用 Audio File Importer 将 WAV 文件导入 Wwise 项目

什么是 Audio File Importer

Audio File Importer 是 Wwise 用于将外部音频文件（.wav）导入项目并自动创建 Sound SFX 对象的工具。它支持批量导入、拖拽、以及按文件夹结构自动组织。

操作步骤

  1. 在 Project Explorer 的 Audio 标签页中， 展开 Actor-Mixer Hierarchy → 右键点击 Default Work Unit。
  2. 选择 Import Audio Files…（或使用快捷键 Shift+I）。
  3. Audio File Importer 对话框打开：
    • 点击 Add Files… 添加单个 WAV 文件
    • 或 Add Folders… 添加整个文件夹
    • 也可以直接从系统文件管理器拖拽文件到对话框中
  4. 确认导入设置：
    设置项选择说明
    Import Mode Create new objects 为每个音频文件创建一个新的 Sound 对象
    Import as Sound SFX 导入为音效对象（对白则用 Sound Voice）
    Object destination Default Work Unit 对象在 Actor-Mixer Hierarchy 中的位置
  5. 点击 Import 完成导入。 如有文件名冲突，会自动弹出 Import Conflict Manager 让你处理。
📥 截图参考：Audio File Importer 对话框 [ 官方截图：Add Files/Add Folders 按钮 | Import Mode 下拉 | Import as 下拉 | Import 按钮 ]

导入后的结果

导入完成后，你会在 Actor-Mixer Hierarchy → Default Work Unit 下看到新创建的 Sound SFX 对象。每个对象都关联了一个对应的 WAV 文件， 可以在 Contents Editor 中查看。

💡 快捷技巧 按住 Ctrl 键直接将文件拖入 Actor-Mixer Hierarchy，可以跳过对话框直接导入。

2.3 用单个 WAV 文件做多种用途

核心技巧：复制 Sound SFX 对象而非重新导入，共享同一份音频文件

⚠️ 考试重点（必考） 判断题：如果你需要用同一个 WAV 文件实现多个不同用途，你必须为每个用途重新导入一次 WAV。→ 答案：错误。应该复制 Sound SFX 对象，两个对象共享同一个 WAV 引用，不会增加内存占用。

为什么这样做

Wwise 中，当一个 WAV 文件被多个 Sound SFX 对象引用时，音频数据在 SoundBank 中 只存储一份。你可以在不增加内存负担的情况下，为同一段音频创建多个独立的声音对象， 各自拥有不同的属性——音高、音量、播放范围、效果器等。

操作步骤（以本课 Gem_Recharge 为例）

  1. 在 Actor-Mixer Hierarchy → Default Work Unit 中找到已导入的 Gem_Recharge Sound SFX 对象。
  2. 选中该对象，在 Transport Control 中按 Space 试听。你会听到一段 先"呼"（woosh）后"叮"（chime）的声音。 这段声音包含两个部分：风声→魔法铃铛声。我们想把它拆成两个独立的音效。
  3. 右键点击 Gem_Recharge → 选择 Copy（或按 Ctrl+C）。
  4. 右键点击 Default Work Unit → 选择 Paste（或按 Ctrl+V）。 Wwise 创建一个名为 Gem_Recharge_01 的副本。
  5. 重命名：
    • 选中原始对象 → 按 F2 → 改名为 Gem_Recharge_Magic
    • 选中副本对象 → 按 F2 → 改名为 Gem_Recharge_Woosh
📋 截图参考：复制 Sound SFX 对象 [ 官方截图：右键 Default Work Unit → Paste，生成 Gem_Recharge_01 ]

验证：两个对象共享同一份 WAV

在 Contents Editor 中分别查看两个对象——它们引用的都是同一个 Gem_Recharge.wav 文件。WAV 文件没有被复制， 只是创建了第二个指向它的 Sound SFX 对象。

💡 关键认知 在 Wwise 中创建声音变化时，复制 Sound SFX 对象 + 编辑属性 远比 重新导入或导出多个 WAV 更高效。这是 Wwise 工作流中最重要的思维方式之一。

2.4 用 Source Editor 独立编辑音频源

在不影响原始 WAV 的前提下，为每个 Sound SFX 对象裁剪不同的播放片段

什么是 Source Editor

Source Editor（音频源编辑器）允许你为每个 Sound SFX 对象 独立定义它的播放范围（Trim），而不影响硬盘上的原始 WAV 文件。 这意味着两个对象可以共享一个 WAV 文件，但播放完全不同的片段。

操作步骤

  1. 编辑 Woosh 部分：
    选中 Gem_Recharge_Woosh → 在 Contents Editor 中双击音频源图标。
  2. 此时打开 Source Editor，你会看到音频的波形图：
    • 拖动 Trim End（绿色结束标记）到风声结束的位置—— 大约在波形图中段，刚好在"叮"声开始之前。
    • 现在播放这个对象，只会听到"呼"声。
  3. 编辑 Magic 部分：
    选中 Gem_Recharge_Magic → 双击音频源图标。
  4. 在 Source Editor 中：
    • 拖动 Trim Start（绿色起始标记）到"叮"声开始的位置。
    • 现在播放这个对象，只会听到"叮"声。
  5. 你还可以为各自的音频源添加 Fade In / Fade Out 来平滑播放的起止。

2.5 创建 Event 并关联声音对象

Event 是连接游戏和 Wwise 声音的核心机制

📌 Event 是什么？ Event 是 Wwise 中最核心的概念之一。游戏引擎通过调用一个 Event （如 PostEvent("Fire_IceGem_Player")）来告诉 Wwise 执行某个动作（播放、停止等）。 Event 就是一个"指令集合"：你告诉 Wwise 收到信号时具体要做什么。

操作步骤

  1. 在 Project Explorer 中切换到 Events 标签页。
  2. 右键点击 Default Work Unit → New Child → Event（或点击工具栏的 Event 图标）。
  3. 命名 Event：输入 Fire_IceGem_Player。 Event 的命名需要与游戏代码中的调用名称完全一致。Cube 中已经预设了此调用。
  4. 双击新创建的 Event，打开 Event Editor。 你会看到一个空的 Actions 列表。
  5. 添加动作：
    从 Audio 标签页将 Gem_Recharge_Woosh 拖拽到 Event Editor 的 Actions 区域。 Wwise 自动创建一个 Play Action，目标就是你拖入的 Sound SFX 对象。
  6. 再次拖拽 Gem_Recharge_Magic 到 Actions 区域。
  7. 设置延迟：选中第二个 Action（Magic），在右侧 Action Settings 中找到 Delay 字段， 输入 0.5（秒）。 这意味着 Woosh 先播放，0.5 秒后 Magic 接上。
  8. 最终 Event 的 Actions 列表：
    顺序Action 类型目标对象延迟
    1PlayGem_Recharge_Woosh0 秒
    2PlayGem_Recharge_Magic0.5 秒
⚡ 截图参考：Event Editor [ 官方截图：Actions 列表 | Play Action | Delay 字段设置 ]

在 Wwise 中试听 Event

选中 Event 后按 Space 可以直接试听整个 Event 的效果。 你会先听到"呼"，片刻后听到"叮"。

💡 一个 Event 可以有多个 Actions Play、Stop、Pause、Resume、Break、Set State、Set Switch、Set RTPC——这些都可以组合在同一个 Event 中。 这让你可以用单一的游戏调用触发复杂的音频行为。

2.6 生成 SoundBank

将 Event 和音频资源打包成游戏可加载的 SoundBank 文件

什么是 SoundBank

SoundBank 是一个 .bnk 文件，包含了 Wwise 自动打包的：

  • 音频数据 — 经过平台编码的 .wem 文件
  • Event 定义 — 告诉 Wwise 收到调用时如何响应
  • 结构信息 — Sound 对象的层级关系和属性设置

游戏在运行时通过 LoadSoundBank() 加载它。

操作步骤

  1. 按 F7 切换到 SoundBank Layout。 也可以通过菜单 Layouts → SoundBank。
  2. 在 SoundBank Manager 中，选择 Default Work Unit，点击 New…。
  3. 命名 SoundBank：输入 Main。 Cube 游戏默认加载名为 "Main" 的 SoundBank。名称必须匹配。
  4. 在 Event Viewer（SoundBank Layout 左下方）中找到 Fire_IceGem_Player → 拖拽到 SoundBank Editor 的 Add 标签页中。
  5. 确认 SoundBank Editor 中显示了你的 Event： Event 下面的所有 Sound SFX 对象和 WAV 都会自动被包含进来。
  6. 点击 Generate Selected（或 Generate All） 生成 SoundBank。
  7. 在 Generating SoundBanks 进度对话框中等待完成， 点击 Close。

3.2 创建 Random Container

Random Container 是 Wwise 中实现声音变化的核心工具

什么是 Random Container

Random Container（随机容器）是一种容器对象，里面可以放多个 Sound SFX 对象。每次触发播放时，Wwise 从子对象中随机选取一个 来播放。这让你用少数几个 WAV 就能获得丰富的播放变化。

操作步骤

  1. 在 Project Explorer 的 Audio 标签页中， 展开 Actor-Mixer Hierarchy → 右键点击 Default Work Unit。
  2. 选择 New Child → Random Container。
  3. 命名为 Gem_Drop，按 Enter 确认。
  4. 导入音频文件：右键点击 Gem_Drop → Import Audio Files…（Shift+I）。
  5. 浏览到课程素材 Module 3 > Audio files 目录， 选择所有宝石掉落（Gem Drop）相关的 WAV 文件 → 点击 Import。 导入完成后，这些 Sound SFX 对象会自动成为 Gem_Drop Random Container 的子对象。
🎲 截图参考：Random Container 的 Contents Editor [ 官方截图：Gem_Drop 容器展开，显示多个 Sound SFX 子对象 ]

Random Container 的三种播放模式

模式行为适用场景
Standard 每次随机选一个，可能连续重复 不需要避免重复的场景
Shuffle 把所有子对象打乱顺序排队，全部播完一轮前不会重复 需要最大变化感、避免任何重复的场景

3.3 用 Randomizer 创造声音变化

即使只用同一个 WAV，也可以通过随机化属性让每次播放都不同

什么是 Randomizer

Wwise 中几乎每个属性（音量、音高、低通滤波等）都有一个 Randomizer（随机化器）开关。开启后，每次播放时 Wwise 会在 你设定的范围内随机取一个值。这样即使是同一个 Sound SFX 对象，每次播出来的效果也略有不同。

操作步骤：音高随机化（Pitch Randomization）

  1. 选中 Gem_Drop Random Container。
  2. 在 Property Editor 中找到 Voice 分组下的 Voice Pitch 滑杆。 单位是 cents（音分），1200 cents = 1 个八度。
  3. 点击滑杆右侧的 Randomizer 开关按钮（图标通常是一个骰子或波形+问号）。 点击后会展开 Min 和 Max 两个输入框。
  4. 设置范围：
    • Min（最小值）：-200
    • Max（最大值）：+200
    这个范围表示每次播放时，音高在 ±200 cents（约 ±1 个半音加一大半）之间随机偏移。
  5. 按 Space 反复播放几次，你会听到每次的音高都略有不同。 每次点击播放，Wwise 都重新随机取一个值。
🎚️ 截图参考：Voice Pitch 的 Randomizer 设置 [ 官方截图：Property Editor → Voice Pitch → Randomizer 开关打开 → Min:-200 Max:+200 ]

进阶：给其他属性也加上随机化

除了音高，你还应该给 音量 和 低通滤波（LPF） 加上随机化，让变化更丰富：

属性推荐范围效果
Voice Volume Min: -3 / Max: +3（dB） 每次播放的音量略有细微变化
Voice Pitch Min: -200 / Max: +200（cents） 音高在约 ±1 个半音内随机
Voice Low-pass Filter Min: 0 / Max: 15 每次的高频过滤程度略有不同，模拟真实环境
📌 Randomizer 的累积规则（考试重点） Randomizer 的偏移值是从对象的基础值 + 父级容器的偏移累积而来的。 如果你在 Random Container 上设置了 ±200 的 Pitch 随机化，而容器内的子对象又设了 ±100，那么最终播放时的随机偏移范围为 ±300 cents。

这就是所谓"Randomizer Accumulation（随机化器累积）"。

3.4 设置 Weight（权重）

控制 Random Container 中每个子对象被选中的概率

什么是 Weight

Weight（权重）允许你控制不同声音出现的概率。 不是所有子对象出现的概率都相同——你可以让某个声音 60% 的时间被选中， 另一个只有 10%。

操作步骤

  1. 选中 Gem_Drop Random Container。
  2. 在 Contents Editor 中，你会看到一个 Weight 列。 默认所有子对象的 Weight 都是 50（均等概率）。
  3. 为不同的子对象设置不同的 Weight 值：
    • 想让某个声音出现概率更高 → 给它更大的 Weight（如 100）
    • 想让某个声音出现概率更低 → 给它更小的 Weight（如 10）

概率计算公式：每个子对象的选中概率 = 它的 Weight ÷ 所有子对象的 Weight 总和。

💡 实际应用示例 脚步声：绝大多数脚步声是正常的（Weight = 100），偶尔掺杂脚踝扭到的声音（Weight = 5）。 这样玩家在 20 次脚步中大概只会听到 1 次扭脚声，既丰富了细节又不会显得突兀。

手枪声：正常枪声 Weight = 90，带消音器效果的枪声 Weight = 10（让 10% 的枪声有一种远程感）。

3.5 创建 Event 并生成 SoundBank

将 Random Container 绑定到 Event，打包输出

创建 Event

  1. 在 Actor-Mixer Hierarchy 中右键点击 Gem_Drop → 选择 New Event → Play。 Wwise 自动创建一个名为 Play_Gem_Drop 的 Event，且已经包含了一个 Play Action。
  2. 切换到 Events 标签页，找到刚创建的 Play_Gem_Drop → 按 F2 重命名为 GemDrop_Player（与 Cube 游戏代码中的调用名称匹配）。

生成 SoundBank

  1. 按 F7 切换到 SoundBank Layout。
  2. 在 SoundBank Editor 的 Add 标签页中， 将 GemDrop_Player Event 拖入。
  3. 点击 Generate Selected 生成。
  4. 等待完成后点击 Close。

3.6 在 Soundcaster 中测试

使用 Soundcaster 在不连接 Cube 的情况下反复触发 Event 验证变化效果

什么是 Soundcaster

Soundcaster 是 Wwise 内置的调试和预览工具。 它模拟游戏中的调用，让你可以在不运行游戏的情况下反复触发 Event， 测试各种 State/Switch 组合。对验证 Random Container 和 Randomizer 效果尤其有用。

操作步骤

5.3 创建 RTPC — 用 PlayerHealth 控制心跳音量

第一个 RTPC 曲线：生命值越低，心跳声越大

什么是 RTPC

RTPC（Real-Time Parameter Control，实时参数控制）是 Wwise 中最强大、 最常用的功能之一。它允许你建立一个映射关系：

Game Parameter 的值（X 轴） → 声音对象属性（Y 轴）

通过编辑 RTPC 曲线，你可以定义当 X 值变化时 Y 值如何变化。

操作步骤

  1. 在 Audio 标签页的 Actor-Mixer Hierarchy 中， 找到 Heartbeat Sound SFX 对象并选中它。 Module 5 项目已经预先导入了心跳声 WAV。
  2. 在 Property Editor 中确认：
    • Loop 已勾选（心跳声需要循环播放）
  3. 切换到 RTPC 标签页（Property Editor 的标签页之一）。 如果看不到 RTPC 标签页，可能需要向右滚动标签页栏。
  4. 点击 RTPC 标签页中的 >>（Next Available Slot）按钮来添加一条新的 RTPC 绑定。
  5. 在弹出的选择器中依次设置：
    • X 轴（输入）：在浏览器中选择 Game Syncs → Game Parameters → Default Work Unit → PlayerHealth
    • Y 轴（输出属性）：选择 Voice → Voice Volume
  6. 此时出现一条红色的斜线——这是默认的 RTPC 曲线。 默认曲线是线性的：X=0→Y=0, X=100→Y=100。但这不符合我们的需求。

我们需要以下映射关系：

PlayerHealth（X）Voice Volume（Y）听觉效果

50约 -200 dB仍然几乎听不到
25约 -12 dB开始能感知到心跳
0（死亡）0 dB心跳声最大

  2. 添加中间控制点：在曲线图的 X≈50 位置双击添加一个新控制点， 并将其 Y 值也拖到约 -200 dB。
  3. 调左端点：将 X=0 处的控制点 Y 值设为 0 dB。

5.4 创建第二条 RTPC — 低通滤波曲线

让心跳声在低血量时不仅变大，还变得更"清晰"

为什么加 LPF RTPC

仅改变音量还不够真实。在真实世界中，当人健康状态下，心跳声是被"包裹"在身体里的——高 频成分被身体组织吸收，听起来比较闷。当心跳剧烈时（低血量），声音更清晰、更多高频成分。

Voice Low-pass Filter（低通滤波，LPF）控制有多少高频成分被滤掉：

  • LPF = 100% → 高频全被滤掉，声音非常"闷"（模拟健康状态下的心跳）
  • LPF = 0% → 不过滤，声音完全"清晰"（模拟剧烈心跳）

操作步骤

  1. 保持 Heartbeat 对象选中，在 RTPC 标签页中再次点击 >> 添加第二条 RTPC。
  2. 设置：
    • X 轴：同样选择 PlayerHealth
    • Y 轴：选择 Voice → Voice Low-pass Filter
  3. 编辑蓝色的 LPF 曲线：
    • X=100 处的控制点 → Y = 100（满血：高频全滤掉，心跳闷）
    • 在 X≈60 处双击添加控制点 → Y = 100
    • X=0 处的控制点 → Y = 0（濒死：高频完全通过，心跳清晰）
  4. 右键点击 X=60 到 X=0 之间的曲线段 → 设置为合理的过渡曲线。

现在 Heartbeat 对象有两条 RTPC 曲线，同时受 PlayerHealth 控制：

PlayerHealth音量LPF听觉效果
100（满血）-200 dB100%完全无声
50~ -200 dB~100%几乎听不到，闷
25~ -12 dB~40%能听到，开始变清晰
0（死亡）0 dB0%最大声，最清晰

6.2 创建 State Group 与 State

什么是 State Group？

📌 核心概念
  • State Group（状态组）：State 的容器，代表"一类全局游戏状态"（如生命状态、天气状态）
  • State（状态）：State Group 内的具体选项（如 Alive / Defeated）
  • State 是全局的：当游戏调用 SetState()，所有订阅了该 State Group 的声音对象都会响应
  • 与 Switch 的区别：Switch 是每个 Game Object 独立的，State 是全局的

  2. 在 Game Syncs 面板中，找到 States 区域
  3. 右键点击 Default Work Unit（或你创建的工作单元）， 选择 New Child → State Group
  4. 将新创建的 State Group 命名为 PlayerLife 命名规则：只能使用字母、数字和下划线，首字符必须是字母或下划线
  5. 右键点击刚创建的 PlayerLife State Group， 选择 New Child → State
  6. 创建第一个 State，命名为 Alive（存活）
  7. 再次右键 PlayerLife State Group，创建第二个 State，命名为 Defeated（阵亡）

6.3 设置过渡时间（Transition Time）

State 的核心特性：可以定义状态切换的平滑过渡时长

💡 为什么需要过渡时间？ 如果没有过渡时间，State 切换会瞬间完成 —— 心跳声突然消失，听起来很生硬。 设置过渡时间后，Wwise 会在指定时长内平滑插值属性值，实现自然的淡出效果。
  1. 在 Game Syncs 面板中 双击 PlayerLife State Group， 它将在 Property Editor（属性编辑器）中打开
  2. 在 Property Editor 中找到 Default Transition Time（默认过渡时间）参数 默认值为 0，表示无过渡，瞬间切换
  3. 将 Default Transition Time 设置为 2（秒） 这意味着 Alive ↔ Defeated 之间的切换将在 2 秒内平滑完成

自定义过渡时间（可选进阶）

如果需要不同方向使用不同过渡时间（例如：死亡淡出慢、复活切入快）：

  1. 在 Property Editor 的 Custom Transition Time 区域点击 Insert
  2. 设置 From: Alive， To: Defeated， Time: 5.0 秒 A→B 方向：心跳声 5 秒淡出（死亡时）
  3. 再点击 Insert， 设置 From: Defeated， To: Alive， Time: 1.0 秒 B→A 方向：心跳声 1 秒切入（复活时）
🖼 截图占位：Property Editor — PlayerLife State Group 属性 Default Transition Time = 2；Custom Transitions 区域可见 From: Alive → To: Defeated (5s) 和 From: Defeated → To: Alive (1s)
⚠️ 注意 本课使用 Default Transition Time = 2 秒 即可。自定义过渡时间是进阶功能，考试可能会问到"如何设置不同方向的过渡时间"。

8.4 编辑衰减曲线

衰减曲线定义了声音属性如何随距离变化 —— 最多 7 条曲线同时作用

衰减曲线属性一览

曲线颜色控制内容典型用法
Volume ■ 红色 音量随距离衰减 距离越远声音越小（核心曲线）
Low-Pass Filter ■ 蓝色 高频随距离减少 远处声音更闷（空气吸收模拟）
High-Pass Filter ■ 绿色 低频随距离减少 远处低频轰鸣减弱
Spread ■ 橙色 声音在扬声器间的扩散宽度 近距离宽泛有包围感，远距离集中为点声源
Center % 紫色 路由到中置扬声器的信号比例 对白等重要声音近距离集中到中置
Bus Send 1 / Bus Send 2 — 发送到 Aux Bus（混响等）的电平 远处声音混响发送量增加
  1. 在 Attenuation Editor 的曲线选择器中，确认 Volume 曲线已启用（红色） 默认有一条从 (0, 0dB) 到 (Max Distance, -∞) 的直线
  2. 设置 Max Distance（最大距离）：输入 500（单位与游戏世界一致，通常是米或厘米） 超出此距离后，声音完全听不见
  3. 在曲线上添加控制点：在距离 ~200 处 双击 添加一个点，拖拽调整到约 -12 dB
  4. 点击曲线段可以切换插值类型：Linear（线性，推荐）、Logarithmic（对数）、Exponential（指数）、Constant（恒定）
  5. 启用 Low-Pass Filter 曲线（点击蓝色选择器）， 添加控制点：距离 0 → LPF 0%（完全清晰），距离 Max Distance → LPF 100%（完全闷）
  6. 启用 Spread 曲线（点击橙色选择器）， 设置距离 0 → Spread 100%（全包围），距离 Max Distance → Spread 0%（点声源）
💡 CPU 性能提示
  • 使用线性线段（Linear）而不是曲线段，CPU 开销更低
  • 每条曲线控制点越少越好（2-3 个点通常足够）
  • 不需要的曲线不启用（Wwise 不会计算未启用的曲线）
🖼 截图占位：Attenuation Editor — 三条曲线均已配置 红色 Volume 曲线：对角线+中间控制点；蓝色 LPF 曲线：从 0 到 100% 递增；橙色 Spread 曲线：从 100 到 0% 递减

8.5 设置 Cone Attenuation（声锥衰减）

让声音随朝向变化 —— 站在 Teleporter 前方比后方听起来更清晰

📌 Cone Attenuation 原理 声锥衰减模拟的是声音的方向性。想象一个喇叭：正前方最响，侧面稍弱，正后方最闷最轻。 Wwise 用内外锥角来定义这个区域：
  • Inner Angle（内锥角）：此角度范围内声音完全正常（满音量）
  • Outer Angle（外锥角）：此角度之外声音达到最大衰减
  • 内外锥之间的区域：衰减从 0% 平滑过渡到 100%
  1. 在 Attenuation Editor 中，找到 Cone Attenuation 区域， 勾选 Enable Cone Attenuation
  2. 设置 Inner Angle（内锥角）：45° 在 Teleporter 正前方 45 度锥角内，声音完全正常
  3. 设置 Outer Angle（外锥角）：135° 超过 135 度（即走到 Teleporter 后面），声音达到最大衰减
  4. 设置 Cone Max Attenuation：-12 dB 站在 Teleporter 后方时，音量比前方低 12 dB
  5. 可选：设置 Cone LPF 为 50% 站在后方时额外叠加低通滤波，使声音更沉闷
🖼 截图占位：Attenuation Editor — Cone Attenuation 设置 Cone Attenuation 区域：Inner Angle = 45°, Outer Angle = 135°, Max Attenuation = -12 dB, Cone LPF = 50%；右侧有锥形可视化预览图

在 Attenuation Editor 中预览 Cone 效果

  1. 在 Attenuation Editor 的预览区，拖拽 小红点（Listener）到不同位置测试
  2. 围绕中心（Emitter）旋转 Listener，在锥角内外切换，实时听到 Cone Attenuation 的效果
  3. 也可以沿距离轴拖拽 Listener 来测试距离衰减叠加 Cone 衰减的综合效果

9.4 配置播放行为

定义路径如何被触发和循环播放

  1. 在 Position Editor 的播放控制区域，设置 Play Type（播放类型）：
    • Sequence：按列表顺序从上到下依次播放各路径
    • Random：随机选择一条路径播放
    本课只有一条路径，两种设置效果相同
  2. 设置 Play Mode（播放模式）：
    • Continuous：持续播放所有路径 → 出现 Loop 和 Transition 选项
    • Step：每次触发声音时播放一次路径

11.4 理解属性继承机制

Wwise 属性分为两大类 —— 相对属性和绝对属性，继承行为完全不同

相对属性（Relative Properties）— 累积叠加

📌 每层级的值相加，最终值 = 所有层级的总和
属性范围继承方式
Voice Volume-200 ~ +200 dB父级 + 子级 + 孙级... 累加
Voice Pitch-2,400 ~ +2,400 cents父级 + 子级 + 孙级... 累加
Voice LPF0 ~ 100%父级 + 子级 + 孙级... 累加
Voice HPF0 ~ 100%父级 + 子级 + 孙级... 累加

示例：Main_Character Actor-Mixer 的 Volume = -6 dB， Heartbeat Sound SFX 的 Volume = -3 dB， 则运行时 Heartbeat 的实际音量 = -9 dB（-6 + -3）。

绝对属性（Absolute Properties）— 覆盖继承

📌 父级设置传递到所有子对象，子对象可 Override 覆盖
属性继承方式
Output Bus父级设定 → 所有子对象路由到同一 Bus（子对象可 Override）
Positioning父级设定 2D/3D → 所有子对象继承（子对象可 Override）
RTPC父级绑定的 RTPC → 所有子对象共享
States父级订阅的 State Group → 所有子对象共享
💡 内存优化关键 在 Actor-Mixer 上设置 Positioning = 3D，其下 10 个子声音共享同一份 Positioning 数据， 比每个子声音单独设置 3D 节省约 10 倍内存。 这就是为什么合理使用 Actor-Mixer 不仅让项目更整洁，还能提升性能。

⚠️ 注意：Effects 在 Actor-Mixer 上的陷阱 在 Actor-Mixer 层级添加效果器虽然方便管理，但不会节省 CPU。 每个子对象都会独立运行该效果器实例。如果需要对所有子对象应用同一个效果且节省 CPU， 应该将效果器放在 Audio Bus 上（第 12 课内容）。

11.6 Override 父属性——子对象独立设置

当某个子对象需要不同于父级的设置时，使用 Override

  1. 在 Actor-Mixer Hierarchy 中，选中需要独立设置的子对象（例如 Heartbeat）
  2. 在 Property Editor → General Settings 选项卡中， 找到 Output Bus 属性
  3. 勾选 Override parent 复选框 勾选后，该属性不再从父级继承，而是使用自己的独立值
  4. 将 Output Bus 改为不同的目标 Bus 每个绝对属性需要单独 Override
📌 Override 注意事项
  • Override 只对绝对属性有效（Output Bus、Positioning、RTPC、States 等）
  • 相对属性（Volume、Pitch、LPF）不需要 Override —— 它们始终可以独立设置，会自动与父级累加
  • Override 后，该子对象的所有后代也会继承这个新值（级联效应）

12.4 追踪信号流：从源到输出

理解一个声音从 WAV 文件到扬声器的完整路径

完整信号链路

  1. Audio Source（WAV 文件） → 原始音频数据
  2. Sound SFX 对象 → 应用 Voice Volume / Voice Pitch / Voice LPF 等相对属性偏移
  3. Actor-Mixer 层级 → 逐层叠加父级的相对属性偏移（Volume 累积）
  4. Output Bus 属性决定路由 → 信号离开 Actor-Mixer Hierarchy，进入 Master-Mixer Hierarchy 的目标 Bus
  5. Bus 链处理 → 每个 Bus 叠加 Bus Volume、Bus Pitch、Bus LPF、Effects、Ducking、States、RTPCs
  6. Master Audio Bus → 所有 Bus 的最终汇集点，最后的总母线处理
  7. 输出到声卡/平台 → 最终立体声（或环绕声）信号

Voice Pipeline（声部管线）—— 最终音量公式

运行时 Wwise 对每个 Voice 的最终音量计算：

Final Volume = Source Volume
+ Actor-Mixer 层级 Voice Volume 偏移（所有父级累加）
+ Bus Volume（路由链上每个 Bus 的 Bus Volume 累加）
+ Attenuation（距离衰减，如果有 3D Positioning）
+ RTPC 驱动的属性变化
+ State 驱动的属性偏移
+ Ducking（闪避）效果

13.4 设置 Auto-Ducking（自动闪避）

当对白播放时，自动降低音乐和音效的音量 —— 这是游戏混音的标准做法

📌 Ducking 原理 Auto-Ducking 允许一个 Bus（如 Voice）的音频信号自动触发另一个 Bus（如 Music）的音量降低。 当 Voice Bus 检测到信号时，Music Bus 的音量在 Fade Out 时间内降到设定值； 当 Voice 信号停止后，经过 Recovery Time，Music 在 Fade In 时间内恢复原音量。
  1. 在 Master-Mixer Hierarchy 中，选中 Voice Bus
  2. 在 Property Editor 中切换到 Auto-Ducking 选项卡
  3. 点击 Insert 按钮
  4. 在 Project Explorer Browser 中选择 Music Bus，点击 OK Music Bus 出现在 Ducking 目标列表中
  5. 再次点击 Insert，选择 Environmental Bus Environmental（含其子 Bus SFX）也会被 Ducking

13.5 配置 Ducking 参数

精细调整闪避的幅度、速度和恢复时间

  1. 在 Auto-Ducking 列表中选中 Music，设置：
    • Volume：-12 dB（对白出现时音乐降低 12 dB）
    • Fade Out：0.5 秒（音乐在 0.5 秒内淡出到 -12 dB）
    • Fade In：1.0 秒（对白结束后 1 秒内淡回到正常音量）
    • Curve：Logarithmic（对数曲线，过渡更自然）
  2. 选中 Environmental，设置：
    • Volume：-6 dB（音效降低幅度比音乐小，保持游戏反馈）
    • Fade Out：0.3 秒
    • Fade In：0.8 秒
  3. 在 Auto-Ducking 选项卡底部设置全局参数：
    • Recovery Time：0.3 秒（对白停止后等待 0.3 秒才开始 Fade In）
    • Maximum Ducking Volume：-24 dB（所有被 Duck 的 Bus 最多降到 -24 dB）

📌 Rendering 的优势与限制
优势限制

16.5 State-Dependent Mixing（基于状态的混音）

为不同的游戏状态设置不同的推子值 —— 实现"动态混音快照"

  1. 在 Mixing Desk 中找到 States 行， 为通道条分配 State Group
  2. 例如为 Music Bus 分配 PlayerLife State Group：
    • Alive 状态：Music Bus Volume = 0 dB（正常音量）
    • Defeated 状态：Music Bus Volume = -12 dB（压低音乐）+ LPF = 60%（变闷）
  3. 使用 Editing States 下拉菜单在不同 State 之间切换编辑
  4. 工具栏中的 Follow States（跟随状态）：
    • 🟢 启用：Mixing Desk 自动跟踪游戏传来的 State 变化，显示当前 State 的属性值
    • 🔴 禁用：锁定在当前编辑的 State，不随游戏变化（离线调整用）
  5. Push States（推送状态）：
    • 🟢 启用：在 Mixing Desk 中切换 State → 改变被推送到游戏/Transport Control/Soundcaster
    • 🔴 禁用：切换仅本地有效，不影响游戏运行

Copy State Values（复制状态值）

  1. 点击 Mixing Desk 工具栏的 Copy States Values 按钮
  2. 选择 From State（源状态）和 To State（目标状态）
  3. 选择要应用到的对象
  4. 点击 OK → 快速复用设置（例如：从 Healthy 复制到 Wounded，然后微调）

16.6 连接游戏进行实时混音

Mixing Desk 的真正战场 —— 一边运行游戏，一边实时调整混音

  2. 点击 Start Capture 开始捕获音频活动

    • 🟢 Voice Playback 指示灯：该对象正在播放声音
    • 🟡 Ducking 指示灯：该 Bus 正在被 Ducking
    • 🔴 Effect Bypass 指示灯：效果器被旁通

    • 🟢 绿色（-∞ ~ -6 dB）：安全范围

  1. 在 Soundcaster 中搭建测试场景（离线）
  2. 在 Mixing Desk 中配置通道条和 State 混音
  3. 连接游戏，Follow States + Start Capture

19.1 打开项目并理解内存约束

在上一课中我们创建了 Main（全局）和 DCP_the_core（关卡）两个 SoundBank。本课将学习如何 限制 和 监控 SoundBank 的体积。

🎯 核心概念：游戏平台对音频内存有严格预算（移动端通常只有几MB），SoundBank 必须在预算内才能正常加载。Wwise 提供 Max Size 和 Conversion Settings 两种机制来控制体积。

操作准备

  1. 启动 Wwise，打开 Lesson 19 对应的 Wwise 项目（续接 Lesson 18 的 Main + DCP_the_core 项目）
  2. 启动 Cube 游戏，按 F10 连接 Wwise
  3. 按 F7 切换到 SoundBank Layout（SoundBank 布局）
  4. 在 SoundBank Manager 中观察两个 SoundBank，目前都没有体积限制
📸 SoundBank Manager 显示 Main 和 DCP_the_core 两个 SoundBank

19.2 设置 SoundBank 的 Max Size

⚠️ 考试重点：Max Size 是 设计时（design-time） 的强制工具，只在 Wwise Authoring 中 生成 Bank 时生效。游戏引擎本身无法强制 Bank 大小限制。

操作步骤

  1. 在 SoundBank Manager 中 双击 Main SoundBank，打开 SoundBank Editor
  2. 点击 Edit 选项卡
  3. 在 Edit 选项卡顶部找到 Max Size 属性字段（默认单位为 bytes）
  4. 输入最大体积值，例如 1048576（1 MB）
  5. 回到 SoundBank Manager，右键 Main → 选择 Generate Selected（生成选中）
  6. 如果 Bank 超过限制，底部的 生成日志 会显示错误/警告，提示 Bank 体积超限
📸 SoundBank Editor 的 Edit 选项卡，Max Size 输入框在顶部
💡 实用技巧：实际项目中可先设置一个宽松的 Max Size，逐步收紧。Max Size 的单位可以切换为 KB/MB 方便阅读。
Max Size 值含义典型场景
10485761 MB小型 UI SoundBank
52428805 MB中型关卡 SoundBank
2097152020 MB大型全局 SoundBank

19.3 按体积分析 SoundBank 内容

Edit 选项卡不仅设置 Max Size，更是分析 Bank 体积构成的核心工具。

操作步骤

  1. 在 SoundBank Editor → Edit 选项卡中，观察树状视图（tree view）
  2. 树状视图显示了 Bank 中包含的所有 Event、Sound SFX、容器和媒体文件
  3. 观察各列信息：
    • Object Name（对象名称）
    • Object Type（对象类型）
    • Size（体积 — 该对象贡献的数据量）
  4. 点击 Size 列标题 按体积降序排列，找出最占空间的资源
  5. 展开树节点逐层下钻，最终定位到具体的 WAV 文件
  6. 顶部状态栏显示 SoundBank 的 总大小
📸 SoundBank Editor Edit 选项卡的树状视图，Size 列按降序排列
⚠️ 考试重点：Edit 选项卡显示的是 SoundBank 中每个对象的 完整层级包含关系。这让你可以精准定位哪些 WAV 文件是 "体积大户"，从而有针对性地优化。

19.4 音频格式转换（Conversion Settings）

Wwise 将音频以平台特定格式存储到 SoundBank 中。Conversion Settings 决定了使用哪种编解码器，不同格式在 体积、质量 和 CPU 之间有不同的取舍。

三种主要音频格式

格式压缩比质量文件体积典型用途
PCM无压缩无损最大短促音效、超低延迟需求
ADPCM4:1 固定良好中等脚步声、打击音效
Vorbis6:1 ~ 12:1 可变优秀（中高码率）最小音乐、环境声、长音频

创建和配置 Conversion Settings ShareSet

  1. 打开 Project Explorer → 切换到 ShareSets 选项卡
  2. 右键空白处 → New → Conversion Settings
  3. 命名 ShareSet（例：Vorbis_High）
  4. 双击打开 Conversion Settings Editor
  5. 在格式下拉菜单中选择目标格式：PCM / ADPCM / Vorbis
  6. 对于 Vorbis：设置 Quality 参数（6~8 为良好平衡，数值越高质量越好体积越大）
  7. 可为不同平台（Windows/Mac/iOS/Android）设置不同的转换参数
  8. 点击 OK 保存
📸 Conversion Settings Editor 界面，格式下拉菜单和 Quality 参数

将 ShareSet 应用到音频对象

  1. 在 Project Explorer → Audio 选项卡中选择一个 Sound SFX
  2. 在 Property Editor 中找到 Conversion 属性组
  3. 点击 Override Conversion Settings 复选框
  4. 从下拉菜单中选择之前创建的 ShareSet（如 Vorbis_High）
  5. 重复此操作应用到其他需要优化的音频对象
💡 最佳实践：使用 Conversion Settings ShareSet 是推荐做法 — 修改一个 ShareSet 会同时更新所有引用它的对象，实现集中化管理。避免逐个对象手动设置格式。
⚠️ 考试重点：Vorbis 在磁盘上体积最小，但 解码后需要额外的运行时内存（播放缓冲区）。ADPCM 是原地解码，几乎不产生额外内存开销。这是 "磁盘体积 vs 运行时内存" 的经典权衡。

19.5 在 SoundBank Editor 中监控内存使用

  1. 在 SoundBank 生成后，回到 SoundBank Editor → Edit 选项卡
  2. 观察每个对象显示的数据：
    • Media Size：音频数据在 SoundBank 中的磁盘体积
    • Estimated Memory：运行时预计的内存占用
  3. 特别注意：Vorbis 和 ADPCM 的 运行时内存 可能与 磁盘体积 差异较大
    • PCM：磁盘体积 ≈ 运行时内存（1:1）
    • ADPCM：运行时需要少量解码缓冲区，略大于磁盘
    • Vorbis：解码缓冲区可能在几十到几百 KB，显著大于压缩后的磁盘体积
  4. 在 SoundBank Manager 中可同时选中多个 SoundBank，对比查看它们的总大小
📸 SoundBank Editor 中显示各对象的 Size 和 Estimated Memory

19.6 应用转换并重新生成

完整优化流程

  1. 根据 19.3 的排序结果，确定最大的音频文件
  2. 为长音频（环境声、音乐）创建 Vorbis 格式的 Conversion Settings ShareSet
  3. 为短音效（脚步声、打击音）创建 ADPCM 格式的 ShareSet
  4. 将 ShareSet 分别应用到对应的 Sound SFX 对象
  5. 右键 SoundBank → Generate Selected 重新生成
  6. 检查生成日志：
    • 确认 Bank 总大小已降到 Max Size 以下
    • 若仍超限，尝试降低 Vorbis Quality 或为更多文件切换格式
  7. 在 Cube 中加载 dcp_the_core 地图，逐个触发声音，确认音质仍然可接受
🎯 优化优先级：先优化体积最大的文件（通常是音乐和长环境声），因为同等比例的压缩能节省最多绝对体积。短音效的优化收益相对较小。

20.1 打开项目并理解 CPU 优化

🎯 核心概念：第 19 课关注 内存（SoundBank 体积），第 20 课关注 CPU（处理开销）。游戏中同时播放过多声音会导致掉帧、音频卡顿或 Voice Starvation（语音饥饿），Wwise 通过 Voice Management 机制优雅地处理超载。

操作准备

  1. 启动 Wwise，打开 Lesson 20 对应的项目文件
  2. 启动 Cube，按 F10 连接 Wwise
  3. 按 F6 切换到 Profiler Layout（性能分析器布局）
📸 Profiler Layout 整体界面

20.2 理解 Voice Pipeline（语音管线）

Wwise 处理音频的管线中存在 语音预算（Voice Budget） — 每个正在播放的声音占用一个 Voice。语音数量有上限，超出时系统根据 优先级 逐步降级处理。

三种语音状态

状态英文音频处理时间线说明
🔊 物理语音 Physical Voice 完全处理（DSP、效果、定位） 正常推进 可听，计入物理语音预算
🔇 虚拟语音 Virtual Voice 无音频处理 可继续推进（根据设置） 不消耗 CPU，空闲槽位释放后可恢复
❌ 杀死/饥饿 Killed / Starved 永久终止 停止 无法恢复，语音被彻底丢弃
⚠️ 考试重点：物理 → 虚拟 → 杀死 是渐进过程。语音首先被虚拟化（节省 CPU），如果虚拟队列也满了则由低优先级开始杀死。虚拟语音并不发声，但它们的 播放时间线可以继续推进（取决于设置），以便恢复时从正确位置继续播放。

20.3 设置全局 Voice Thresholds

操作步骤

  1. 打开菜单：Project → Project Settings...（或 Alt + Enter）
  2. 找到 Volume Threshold（音量阈值）设置项：
    • 默认值通常为 -96 dB 或 -80 dB
    • 低于此阈值的声音自动被虚拟化，无论语音预算是否充足
    • 这是一个重要的 CPU 节省机制：人耳听不到的声音不消耗处理资源
  3. 找到 Maximum Number of Voices（最大语音数）：
    • 设置全局可同时存在的 物理语音总数 上限
    • 桌面端通常为 30~50，移动端更低（10~20）
    • 练习中可设为 50 方便观察
  4. 点击 OK 保存设置
📸 Project Settings 窗口中的 Volume Threshold 和 Voice 相关设置

20.4 Voice Priority 与 Playback Limit

Voice Priority（语音优先级）

每个声音对象都有一个 Priority 属性。当语音数达到上限时，Wwise 使用优先级决定哪些语音被虚拟化或杀死：

  • 数值越高 = 优先级越高（范围 1~100）
  • 优先级低的声音先被虚拟化
  • 同等优先级下，最旧的语音 先被杀死
  • 关键游戏音效（UI 确认音、武器发射）应该给高优先级（80~100）
  • 环境氛围音可给低优先级（1~20）

设置操作

  1. 在 Project Explorer 中选中一个 Sound SFX
  2. 在 Property Editor 中找到 Priority 属性（位于 Advanced Settings 或 Voice 区域）
  3. 设置数值：重要音效 80~100，普通音效 50，环境音 1~20
  4. Priority 也可以在 Actor-Mixer 或 Container 层级设置，影响所有子对象

Playback Limit（播放限制）

Playback Limit 限制同一个声音 的最大同时播放实例数：

  1. 选中一个 Sound SFX
  2. 在 Property Editor 中找到 Playback Limit（位于 Advanced Settings）
  3. 勾选 Limit sound instances to: 并设置数值（如 3）
  4. 在 When limit is reached: 下拉中选择行为：
    • Kill voice — 杀死最旧的实例
    • Use virtual voice — 最旧的实例进入虚拟状态
📸 Property Editor 中的 Priority 和 Playback Limit 属性区域
💡 典型例子：脚步声 Playback Limit 设为 8 — 即使有 20 个角色同时在走，最多也只播放 8 个脚步声实例，避免密集脚步声淹没其他重要音效。

20.5 Virtual Voice Behavior 设置

当语音被迫进入虚拟状态时，如何行为是可以配置的：

全局设置

  1. 打开 Project Settings → Voice 区域
  2. 找到 Virtual Voice Behavior（虚拟语音行为），选项包括：
    • Play from elapsed time — 虚拟期间播放位置继续推进，恢复时从经过的位置继续（适合音乐/环境声）
    • Play from beginning — 恢复时从头重新播放（适合一次性音效）
    • Send to virtual voice — 进入虚拟状态遵循项目全局设置
    • Kill — 直接杀死，不进入虚拟

逐对象覆盖

  1. 选中一个声音对象
  2. 在 Property Editor 中找到 Virtual 下拉菜单
  3. 可覆盖全局设置，为该对象指定特定行为
⚠️ 考试重点："Play from elapsed time" 是最常用的虚拟语音模式。想象一段 30 秒的环境音循环 — 如果被虚拟化了 5 秒，恢复时应该从 5 秒后的位置继续，而不是从 0 秒重新开始，否则会产生不连贯的听觉体验。

20.6 使用 Profiler 监控性能

核心监控面板

  1. 按 F6 进入 Profiler Layout
  2. Voice Graph（语音图表）：
    • 纵轴 = 语音数量，横轴 = 时间
    • 实线 = 物理语音数，虚线 = 虚拟语音数
    • 图表顶部触碰上限线 → 说明达到语音限制
  3. Performance Monitor（性能监视器）：
    • 显示实时 CPU 和内存统计
    • CPU Usage 标签显示音频引擎消耗的 CPU 时间（效果器、DSP 等）
  4. Voice Monitor（语音监视器）：
    • 列出当前所有活跃语音
    • 显示每个语音的 物理/虚拟状态、优先级、音量、时长
    • 虚拟语音会被高亮标记
  5. Voice Inspector（语音检视器）：
    • 在 Voice Monitor 中点击任意语音可打开检视器
    • 显示该语音进入虚拟状态的 原因（音量低于阈值 / 超过播放限制 / 优先级不足）
